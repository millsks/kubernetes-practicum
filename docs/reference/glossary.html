Reference · Vocabulary

Glossary

Terms used in Stage 1, with a link to where each is taught.

Terms

API server
The cluster's front door: authenticates, authorises, validates, and stores every object, and serves watches. The only component that talks to etcd. M01
Container runtime
Software that pulls images and runs containers; containerd inside kind nodes. The kubelet talks to it over CRI. M00
Context
A named cluster, user, and default namespace in your kubeconfig. kubectl always uses the current one. M00
Controller
A loop that observes desired and actual state for one kind of object, and acts to close the gap. M01
CRI
Container Runtime Interface: the gRPC API between the kubelet and a runtime. M00
CrashLoopBackOff
A container keeps exiting and the kubelet is waiting, with growing delays, before restarting it. A symptom, not a cause. M02
CronJob
Creates Jobs on a schedule. M03
DaemonSet
Runs one Pod on every matching node. M03
Deployment
Manages ReplicaSets to run stateless replicas and roll between versions. M03
etcd
The consistent key-value store holding all cluster state. M01
Init container
Runs to completion before the app containers start. With restartPolicy: Always it becomes a native sidecar. M02
Job
Runs Pods until a number of them succeed, with retries and deadlines. M03
kind
Kubernetes IN Docker: a tool that runs each cluster node as a container. M00
kubelet
The node agent: runs the Pods assigned to its node and reports their status. M01
Label and selector
Key/value pairs on objects, and queries over them. Controllers and Services find Pods by selector. M03
Level-triggered
Acting on current state rather than on individual events, so missed events don't matter. M01
OOMKilled
A container went over its memory limit and the kernel killed it (exit code 137). M02
Pod
One or more containers scheduled together, sharing an IP and volumes. M02
Probe
A health check: startup (has it booted?), readiness (may it get traffic?), liveness (is it wedged?). M02
QoS class
Guaranteed, Burstable, or BestEffort, derived from requests and limits; decides eviction order. M02
Reconcile loop
Observe, diff, act, repeat. M01
ReplicaSet
Keeps a number of identical Pods running. Managed by a Deployment. M03
Request and limit
A request reserves capacity for scheduling; a limit caps usage at runtime. M02
Rolling update
Replacing Pods gradually, bounded by maxSurge and maxUnavailable. M03
Scheduler
Assigns each unscheduled Pod to a node by filtering and scoring. M01
Native sidecar
An init container with restartPolicy: Always that runs alongside the app. M02
spec and status
Desired state (written by you) and observed state (written by the system). M01
StatefulSet
Runs replicas with stable names, stable DNS, and a volume each. M03
